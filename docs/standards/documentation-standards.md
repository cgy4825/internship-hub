# 文档书写规范

> 本仓库所有 markdown 文档统一遵守以下约定。目的是让文档可读、可维护、可追溯。

## 1. 格式约定

- 首行是 `# 标题`，作为文档主标题（每个文件只有一个 H1）。
- 用 `---` 分隔主标题与正文（若需要 front matter 风格）。
- 章节使用 H2（`##`），子章节 H3（`###`），不要跳级。
- 中英文之间建议留一个空格（如 "前端 与 后端"），提升可读性。
- 代码块统一标注语言（` ```ts `、` ```python `、` ```json `、` ```md `）。

## 2. 内容结构

每个标题内容型文档尽量遵循：

1. **目的/说明** —— 这个文档讲什么
2. **正文** —— 表、代码、解释
3. **表格** —— 用 markdown 表格表达结构化信息（字段表、配置表）
4. **链接** —— 相对链接指向同仓库其他文档，不要用绝对路径/外链替代内部文档

## 3. 文档分类

| 分类 | 用途 | 命名规则 | 需要 ADR 吗 |
|------|------|----------|-------------|
| 规范（standards） | 强制标准 | `xxx-standards.md` | 修改需 ADR |
| 架构（architecture） | 系统说明 | `overview.md` / `frontend.md` 等 | 无关 |
| 数据（data） | schema | `schema.md` | 无关 |
| 决策（decisions） | ADR | `NNNN-title.md` | 本身即 ADR |

## 4. 维护规则

- 文档与代码**同步维护**：改代码必须同步改相关文档，否则视为违规。
- 文档一旦被标记为「权威」，其字段定义/规范以该文件为准，其他文件引用它并保持链接。
- 每个文档顶部用一行简短「> 说明」注明其定位（可选但推荐）。
- 不要删除已有章节；废弃内容标注「已废弃」并说明替代文档。

## 5. 进度留痕

- 项目开发阶段在 `docs/` 下用 md 记录，命名建议 `progress/` 或在文档内加「阶段记录」章节。
- 每条记录包含：**阶段**、**日期**、**目标**、**产出**、**验证方式**、**遗留问题**。
