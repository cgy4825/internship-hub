# ADR-0001：技术栈选型

- **状态**：已接受
- **日期**：2025-01-01
- **决策者**：项目发起人 + 开发

## 背景

需要构建一个「大厂实习信息聚合 + 一键跳转投递」的网站。约束：
- 发起人非专业程序员，需尽量降低维护成本。
- 预算很低，尽量近零成本。
- 需要每天更新、支持搜索/筛选/收藏/提醒。

## 决策

| 层面 | 选型 | 理由 |
|------|------|------|
| 前端框架 | React + TypeScript + Vite | 生态成熟、组件化、类型安全，便于做精美 UI |
| 样式 | Tailwind CSS | 快速做出美观且一致的界面 |
| 前端托管 | Vercel / GitHub Pages（免费） | 近零成本，静态资源直出 |
| 数据采集 | Python | 抓取/清洗生态成熟（requests、bs4），易扩展 |
| 数据存储 | JSON 文件（进 git） | 静态站点直接读取，无需数据库，近零成本 |
| 定时任务 | GitHub Actions cron | 免费、无需自家服务器 |
| 包管理器 | npm | 当前环境未安装 pnpm，统一用 npm 降低环境不一致 |

## 备选与取舍

- **不用自建后端 + 数据库**：成本高、复杂度大，与「近零成本」矛盾。MVP 阶段用静态 JSON 足够。
- **不用低代码平台**（如 n8n 自建）：虽免写代码，但定制 UI、扩容、可维护性都受限；且当前自带开发能力（AI 助手），直接写更可控。
- **收藏用 localStorage 而非账号**：MVP 阶段先不上用户系统，最快可用，详见 ADR-0003（若后续需要账号再启用）。

## 后果

- 优点：成本极低、交付快、易扩展数据源。
- 缺点：无用户级云同步收藏；「提醒」需借助 RSS 或后续加邮件服务。
