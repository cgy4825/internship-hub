# ADR-0002：采用静态站点 + 定时采集（近零成本）

- **状态**：已接受
- **日期**：2025-01-01
- **决策者**：项目发起人 + 开发

## 背景

希望网站「每天自动更新实习信息」，同时尽量低成本、低维护。

## 决策

采用「**静态站点 + 定时采集产出静态数据**」架构：

1. 采集器（Python）通过 GitHub Actions **定时运行**（如每天一次）。
2. 采集器抓取各数据源 → 清洗归一化 → 产出 `data/internships.json`，**提交进 git 仓库**。
3. 静态前端（Vercel / GitHub Pages）直接读取该 JSON 渲染。

这样**不需要常驻服务器**，也不需要维护数据库，托管几乎免费。

## 备选与取舍

- **自建后端 + 数据库**：需要常驻服务器，成本与维护复杂度显著上升，违背「近零成本」。放弃。
- **纯手动更新**：数据更新依赖人工，无法满足「每天自动更新」。放弃。

## 后果

- 优点：成本极低、运维简单、数据可版本化（git 历史即数据历史）。
- 缺点：数据更新依赖定时任务；站点不是「实时」而是「准实时（按天）」——但实习信息按天更新正是需求。
- 提醒功能需基于静态数据生成 RSS，邮件提醒需后续加轻量服务。
